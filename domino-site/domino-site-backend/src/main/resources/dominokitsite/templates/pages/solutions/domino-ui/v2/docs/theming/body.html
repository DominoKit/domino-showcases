Theming and styling

Domino UI themes are composable CSS layers. A theme changes semantic variables rather than imposing global element selectors, so an application can theme a Domino UI subtree while continuing to coexist with another UI system on the same page.

Theme layers

Start with the default main theme, then select one value from each replacement category. Identity, accent, density, character, and surface treatments are intentionally separate: changing the accent does not replace the visual identity, and applying elevation does not remove borders or rounding.

  • Main: the core component token set, provided by DominoThemeDefault.
  • Color mode: light or dark.
  • Identity: the dominant application color family, such as Ocean, Forest, or Graphite.
  • Accent: a composable action and emphasis color that retains its own color identity.
  • Density: default or compact spacing and control sizing.
  • Character: a material treatment such as Glass, Paper, Terminal, or Aurora.
  • Surface: independently composable bordered, elevated, rounded, and accent-header treatments.

Compose themes

Apply theme descriptors to the application root, or to a specific Domino UI subtree. Applying another theme in the same category replaces only the earlier value in that category. Surface treatments use separate categories, so they can be enabled and cleared independently.

Use the corresponding clear descriptor when a user turns off a surface treatment. This does not disturb the other selected layers:

Interactive composition Apply modes and accents to one preview subtree without changing its sibling.

Built-in catalog

Include domino-ui-themes.css to make every built-in optional theme available, or include only the individual theme stylesheets your application offers. The Java descriptors and the CSS class names use the same family names, for example DominoThemeIdentity.OCEAN applies dui-theme-ocean.

Surface treatments

Surface themes are deliberately orthogonal. Bordered controls border presentation, Elevated controls shadows, Rounded controls radius, and Accent headers controls the headers of cards, menus, trees, and DataTables. Their CSS variables remain theme-aware, so the treatment keeps contrast in light and dark modes.

Emphasis modifiers

Use emphasis classes to change the surface treatment of an already contextual component. Filled is the default; subtle uses a translucent contextual background and border; minimal keeps a contextual border over a transparent surface. Add the modifier directly to a component, or to a container when the component family supports inherited emphasis. Icons intentionally react only to emphasis placed directly on the icon.

Component emphasisFilled, subtle, and minimal variants on contextual components.

Group emphasisUse a parent modifier only where the component family supports inheritance.

Card emphasisCards support the same contextual filled, subtle, and minimal treatments.

Scoped CSS and custom variables

Domino UI styles are rooted at .dui. Keep application overrides scoped to a Domino root or your own application root rather than styling HTML elements globally. Prefer documented CSS variables over copying component selectors: variables compose with color mode, identity, accent, and nested surfaces.

Contextual palette classes such as dui_blue, dui_success, and dui_error expose --dui-context-color and related background shades. That makes the same component APIs work with predefined and dynamic color schemes.

Accessibility and contrast

Theme tokens choose foreground colors for contextual and interactive surfaces, including progress indicators, toggle buttons, table states, form placeholders, and alerts. When creating a custom theme, test both light and dark modes, keyboard focus, disabled controls, hover states, and subtle/minimal emphasis. Do not communicate meaning only with color; pair state colors with text, icons, or accessible labels.

Fonts

Source Sans 3 is the default body family. Font families are tokenized and can be changed globally or within a dui-font-scope subtree. See Typography for bundled families, custom webfont loading, and form-label typography details.

WaitMe loaders

WaitMe is included as a ready-to-use Domino UI-owned loader stylesheet, but it is not part of the theme token contract. Its classes use the dui-waitme-* convention and it is available in the aggregate CSS bundles, including their minified forms.
