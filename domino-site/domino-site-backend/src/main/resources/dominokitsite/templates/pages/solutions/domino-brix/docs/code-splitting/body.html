Code splitting

Domino Brix can load an independently routed presenter only when its route is first visited. Code splitting is opt-in: presenters without @Split retain the existing eager startup behavior.

Split one presenter

Add @Split to a routed presenter. The default trigger is derived from its @BrixRoute value and uses STARTS_WITH_PATH, so the inventory split below also matches inventory/items. Each split presenter must be referenced by exactly one @BrixComponent.

  • The annotation processor generates a BrixModuleDescriptor that defers the presenter, view, and component initialization behind a GWT split point.
  • When the current token matches the trigger, Brix loads the fragment, registers the route, and replays the current route.
  • Parent and child presenters cannot cross the eager/deferred boundary. If both are split, they must use the same named group.

Group presenters into one split

Set module when several presenters should share one deferred fragment. Every presenter in the group contributes a trigger, and loading any matching route initializes the whole group.

Compile all participants in a named group in the same annotation-processor run (normally the same Maven module). Reusing a group name from separately compiled modules creates conflicting generated descriptors. An ungrouped split presenter can still be discovered from a dependent module that owns its @BrixComponent.

Use an explicit route trigger

Use @RouteTrigger when the split should load for a different token, or when @BrixRoute uses a custom routing provider. With a custom provider, a non-blank explicit trigger is required because Brix cannot infer its matching rule. The default match is STARTS_WITH_PATH; use EXACT_PATH, ENDS_WITH_PATH, or the corresponding fragment modes when needed.

Bootstrap generated modules

Register split descriptors and initialize eager components before firing history or navigating. initModules(...) is the single bootstrap call for both generated service lists.

Build and verify

  • This feature targets classic GWT production compilation. J2CL is currently out of scope.
  • GWT CodeServer/Super Dev Mode does not produce deferred fragments, so use a production compile to verify a split.
  • Add -compileReport to the GWT compiler arguments to generate an SOYC report and inspect the generated split points.
  • Use Brix.get().modules().setFailureHandler(...) to report deferred-load failures and Brix.get().modules().retry(moduleId) to retry a failed module.
